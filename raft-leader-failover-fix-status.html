Root Cause Analysis

Problem

The test testConnectionFailureTriggersFailover failed intermittently (~40% failure rate) with Object 2 returns null after leader failover. The client observed stale data after a successful CREATE operation.

Timeline of the Race Condition

T=0
Client creates Object 2 on new leader
Entry committed and replicated via Raft
T=1
Test calls invalidateLeaderCache()
Clears cached leader, next GET will rediscover
T=2
Client GET routes to follower
Entry not yet replicated to follower → Returns null (NOT_FOUND)
T=3
Raft replication catches up
Object becomes visible everywhere, but test already failed

Root Cause

The client's retry logic in executeWithLeaderRouting() only caught IOExceptions, but MetadataClient.getObject() returns null for NOT_FOUND responses (not an exception). The retry never triggered.

Solution Implemented

  • 1
    Created executeWithLeaderRoutingForObjectGet() method
    New dedicated method in ClusterMetadataClient that handles null returns from getObject() and retries with another server
  • 2
    Enhanced commit future completion logic
    Fixed RaftNode to complete commit future immediately after commit index advances, even when stateMachineApplier is null (integration tests)
  • 3
    Fixed test logic bug in MetadataClientLostResponseRetryTest
    Corrected test to use different object names for each request (original test created same object twice)
