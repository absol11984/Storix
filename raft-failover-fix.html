Problem: Current Fix Only Catches IOExceptions

// In ClusterMetadataClient.executeWithLeaderRouting() // The retry logic only catches IOExceptions } else if (message.contains("Object not found") || message.contains("NOT_FOUND")) { // Object not found on this server System.out.println("[CLIENT] Object not found, trying another server"); cachedLeader = null; closeCurrentClient(); serverIndex++; }

Critical Issue:

MetadataClient.getObject() returns null for NOT_FOUND responses, not an IOException:

// MetadataClient.getObject() returns null for NOT_FOUND if (response.status() == MetadataProtocol.NOT_FOUND) { return null; // NOT an IOException! }

Since no exception is thrown, the retry logic in executeWithLeaderRouting() never triggers!

Proposed Solution

1
Create new retry method for GET operations
Add executeWithLeaderRoutingForObjectGet() that handles null returns from getObject()
2
Throw IOException for NOT_FOUND responses
Or create a wrapper that converts null returns to IOExceptions with NOT_FOUND message
3
Test with new retry logic
Run test multiple times to ensure intermittent failure is resolved
