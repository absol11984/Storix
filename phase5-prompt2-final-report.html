2. Key Implementation Details

Single Authoritative Observability Architecture

Observability.Registry
  ├── Requests (LongAdder, AtomicLong)
  ├── ManagerMetrics (LongAdder)
  └── Lifecycle State (volatile String)

Each MetadataServer → 1 Registry → All Components

Lifecycle State Transitions

STARTING → MetadataServer.start() entry
HEALTHY → after serverChannel binds successfully
STOPPING → MetadataServer.stop() entry

State transitions deterministic, no stuck states

Health State Computation

HEALTHY: All nodes ACTIVE and healthy
DEGRADED: Nodes degraded or recovery-held
UNHEALTHY: No usable storage nodes available

Health computed from actual NodeInfo status

Request Failure Classification

SocketTimeoutException/EOFException → "timeout"
IOException (network) → "unavailable_node"
NOT_LEADER response → "raft_rejection"
Chunk operation failure → "storage_failure"
IllegalArgumentException → "invalid_request"
Other exceptions → "internal"

No more "all IOException → timeout" bug

5. Implementation Quality

Thread Safety

  • All metrics use LongAdder/AtomicLong (thread-safe)
  • Active operation counting with try/finally guarantees
  • No synchronized blocks on hot paths

Memory Bounds

  • No unbounded request history stored
  • Snapshots are detached (immutable copies)
  • No background threads or polling loops

Performance

  • Increments use LongAdder (low contention)
  • No disk I/O or network calls for metrics
  • No global locks on data path

Reliability

  • Metrics survive component restarts
  • Active counts guaranteed to decrement (try/finally)
  • No metric inflation from retries
